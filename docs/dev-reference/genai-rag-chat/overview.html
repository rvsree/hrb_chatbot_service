overview

GenAI RAG Chat

The baseline RAG mode: fixed retrieve-then-generate, no agent loop - the mode every other retrieval mode is measured against.

Overview Spec Architecture Design Decisions Interview FAQ

Purpose

One question in, one grounded answer out, with real citations back to the source PDFs RAG Ingestion indexed. No agent loop, no tool-calling decisions - a fixed pipeline: decompose the query, retrieve the most relevant chunks, generate an answer from exactly what was retrieved. This is the simplest of the three retrieval modes, and deliberately so - it's the control group the two agentic modes (which add a reasoning loop on top of the same retrieval machinery) are measured against.

Every answer is guardrailed and cacheable, since there's no live-data tool call that could make a cached answer stale - unlike the agentic modes, which exclude live-data tools (leave balance, leave history) from caching.

Scope

Covers the full guarded retrieve-then-generate path: input guardrail, query decomposition, configurable search strategy (similarity/MMR/keyword/hybrid), optional MultiQueryRetriever/SelfQueryRetriever, generation with real source citations, output guardrail, conversation-memory load/save, and a Redis answer cache keyed per-pipeline. Also includes a narrow MCP keyword fast-path for a small set of live-data questions a static knowledge base can't answer (e.g. "what's my leave balance") - genai-rag-chat-only, not the full ReAct tool-calling loop the agentic modes use.

Does not cover multi-step tool-calling (that's Single-Agentic RAG) or parallel multi-agent orchestration (that's Multi-Agentic RAG) - this mode never decides to call a second tool mid-answer.

High-level workflow

  1. 1Input guardrail - the query is checked before anything else runs, via the shared guarded_pipeline.py core.
  2. 2Cache check - a pipeline-namespaced Redis lookup; a hit skips straight to step 6.
  3. 3Decompose - the query is broken into sub-questions when it needs more than one retrieval pass.
  4. 4Retrieve - the configured search strategy pulls the most relevant indexed chunks.
  5. 5Generate - the LLM answers from exactly what was retrieved, with citations back to source documents.
  6. 6Output guardrail + memory - the answer is checked, the turn is saved to conversation memory, and the response (with full latency/token/eval breakdown) goes back to the caller.

Where this fits in the HR Benefits RAG system

This is one of three read paths over the index RAG Ingestion writes to. GenAI RAG Chat, Single-Agentic RAG, and Multi-Agentic RAG all query the same vector store, through the strategies described in Retrieval Strategies, and all three funnel through the same guardrail/memory/logging core (Phase 98) so that behavior doesn't drift between modes. GenAI RAG Chat is the one with no reasoning loop at all - pick it when the question is answerable from the knowledge base alone, with no need for the agent to decide what to look up next.
