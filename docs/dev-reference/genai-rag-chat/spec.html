GenAI RAG Chat

Spec Architecture Design Decisions Interview FAQ
1
Intent

The baseline RAG mode - fixed retrieve-then-generate, no agent loop, no tool-calling decisions. One question in, one grounded answer out, with real citations back to the source PDFs. The mode every other retrieval mode (single/multi-agentic-rag) is measured against.

2
Scope
Live todaybuilt
  • Guardrailed retrieve-then-generate via the shared guarded_pipeline.py core (Phase 98) - input guardrail, conversation-memory load/save, output guardrail, logging, uniformly
  • Answer cache (Redis, Phase 78) - shared across all 3 retrieval modes, each with its own pipeline-namespaced key; unlike the agentic modes, genai-rag has no tool-calling step at all, so every one of its answers is unconditionally cacheable (see Decisions GR-2)
  • Configurable search strategy (similarity/MMR/keyword/hybrid), vector DB, LLM provider, top_k, temperature - all per-request overrides
  • MultiQueryRetriever/SelfQueryRetriever (Phase 20) - real LangChain classes, opt-in via use_multi_query/use_self_query
  • MCP keyword fast-path - genai-rag-only (not the full ReAct tool-calling loop the agentic modes use), for a narrow set of live-data questions a static KB can't answer
Explicitly out of scope for this modeby design
  • Multi-step tool-calling / ReAct loops - that's single-agentic-rag's job
  • Parallel multi-agent orchestration - that's multi-agentic-rag's job
  • DeepEval-based scoring - still Phase 174, hand-written scoring (Groundedness/Completeness/Precision/Recall/F1) is what's live
3
Personas
employee / manager / hr_support / adminAll four roles can query - require_role(EMPLOYEE, MANAGER, HR_SUPPORT, ADMIN), uniformly (Phase 178 added ADMIN).
4
Acceptance criteria
Grounded, citable answersmet

Every answer's retrieval_info.sources traces back to a real indexed document - not a bare LLM guess.

Guardrails on every callmet

Input and output guardrail checks run uniformly via the shared core - this project's own Phase 98 was created specifically because single-agentic-rag once shipped with none at all.

Cache transparencymet

explainability_info.served_from_cache always tells the caller whether this was a fresh generation or a cache hit - never silently hidden.

Full observability per callmet

Latency breakdown, token usage, LLM call count, and eval scores all returned per request - not just the answer text.
