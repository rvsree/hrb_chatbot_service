Retrieval Strategies

4 search strategies and 2 optional LangChain rewriting classes - the shared "how do we find the right chunks" layer every retrieval mode uses.

Overview Spec Architecture Design Decisions Interview FAQ

Purpose

Every retrieval mode (GenAI RAG Chat, Single-Agentic RAG, Multi-Agentic RAG) eventually needs to answer the same question: given a query, which indexed chunks are actually relevant? Retrieval Strategies is that shared layer - 4 selectable search strategies behind one gateway dict, plus 2 optional LangChain classes that rewrite or filter the query before it ever reaches a strategy. Not a user-facing feature on its own; it's the retrieval engine every mode calls into.

Scope

Covers 4 real strategies - similarity (plain vector search), mmr (Maximal Marginal Relevance, trades relevance for result diversity), keyword (BM25 lexical ranking, catches exact terms/acronyms vector search can miss), hybrid (BM25 + vector combined via Reciprocal Rank Fusion) - plus 2 optional LangChain rewriting classes layered on top of any of them: MultiQueryRetriever (generates query variants, unions the results) and SelfQueryRetriever (parses metadata filters out of the query text itself). Both rewriting classes run through GatewayChatModel, this project's own adapter over its multi-provider ask() clients - not a per-provider LangChain package.

Does not cover how retrieved chunks get into the index in the first place (that's RAG Ingestion), or what happens to retrieved chunks after this layer hands them off (that's each retrieval mode's own generation step).

High-level workflow

  1. 1Receive - a calling mode hands this layer a query and (optionally) a chosen strategy name.
  2. 2Optional rewrite - if use_multi_query/use_self_query is set, the query is expanded into variants or has metadata filters parsed out first.
  3. 3Strategy dispatch - the named (or default) strategy runs its own real search against the vector store.
  4. 4Rank & return - the matched chunks come back ranked, ready for the calling mode's own generation step.

Where this fits in the HR Benefits RAG system

This sits between RAG Ingestion (which writes the index) and the three retrieval modes (which each read from it through this same layer). An unrecognized strategy name is rejected cleanly as a 422 at the API boundary - this layer never silently falls back to a default or fails deep inside a pipeline. The "Retrieval:" dropdown in the UI's tuning bar is the one place a caller directly chooses a strategy; every other touchpoint with this layer is internal to a retrieval mode's own request handling.
