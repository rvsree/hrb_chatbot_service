GenAI Chat Workflow

Ask questions about files you just attached in the chat composer - a ReAct agent over documents in hand, completely separate from the indexed knowledge base.

Overview Spec Architecture Design Decisions

Purpose

Every other RAG mode in this app answers from documents someone already uploaded and indexed into the shared knowledge base. GenAI Chat Workflow is for the opposite case: a file the user has right now, that doesn't belong in the shared KB at all - a personal benefits summary, a one-off contract, a spreadsheet to ask about. Attach up to 3 files directly in the chat composer, ask a question, and a ReAct agent reads them, decides whether it needs to search the web for anything the files don't cover, and can email the answer on request.

Nothing here is indexed. The file exists for the duration of one request and is never written to S3 or disk - this is deliberately the lightest-weight, most ephemeral RAG surface in the system.

Scope

Covers the full in-request pipeline: file validation and text extraction (PDF/DOCX/CSV), guardrail screening of both the files and the question, a 3-tool ReAct agent (ReadDocument, SearchWeb, SendEmailWithAnswer), always-on session memory so a follow-up turn can reference what was discussed, and two independent email paths - the agent's own in-text decision, and a checkbox the UI drives directly.

Does not cover indexing or persistence of file content - a file asked about here is never searchable by any other feature, and a new session starts with no memory of files from a previous one.

High-level workflow

  1. 1Validate & extract - up to 3 files are checked (type, size) and their text extracted, entirely in-request.
  2. 2Guardrail - each file's text and the question itself are screened independently before the agent sees them.
  3. 3Load session history - if continuing a session, prior turns are loaded so the agent has conversational context.
  4. 4Agent reasons - the ReAct loop decides whether it needs to read a specific file, search the web, or has enough to answer already.
  5. 5Answer & (maybe) email - a grounded answer returns, with an email sent if the agent decided to or the checkbox was set.
  6. 6Persist - the turn is saved to session memory, including a hidden note on any email outcome, so a later turn can answer "did you send it?" correctly.

Where this fits in the HR Benefits RAG system

This is the one RAG-adjacent feature that deliberately doesn't touch the main pipeline at all - it shares no code with RAG Ingestion, Retrieval Strategies, or any of the three retrieval modes. Where those features all answer from the shared knowledge base, this one answers from whatever the user hands it directly, right now. It's reachable from the chat page's "Enable GenAI Chat Workflow" checkbox, a separate mode from the "RAG Pipeline:" selector the other three modes share.
