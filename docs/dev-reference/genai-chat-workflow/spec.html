spec - intent, scope, personas, acceptance criteria

GenAI Chat Workflow

Ad-hoc document Q&A, attached directly in the chat composer - a ReAct agent over files the user just uploaded, deliberately separate from the main RAG pipeline (no indexing, no persisted KB state).

Spec Architecture Design Decisions
1
Intent

A one-off way to ask questions about files the user has in hand right now - a benefits summary PDF, a contract, a spreadsheet - without uploading them to the shared knowledge base. A ReAct agent reads the attached files, decides whether it needs to search the web for anything the files don't cover, and can email the answer on request. Completely separate code path from ai/rag_pipeline/ and ai/doc_processing/ indexing - nothing here ever touches the shared vector store.

2
Scope
Live todaybuilt
  • Up to 3 files per request (PDF/DOCX/CSV, 10MB each) - extracted to plain text in-request, nothing written to S3 or disk
  • A real ReAct agent with 3 tools: ReadDocument, SearchWeb, SendEmailWithAnswer
  • Session memory (Phase 163) - always-on for this workflow, unlike the other 3 modes' opt-in enable_conversation_memory
  • Two independent email paths that can both fire in the same turn: the agent's own in-text decision, and a checkbox-driven path the UI drives directly
  • Same input/output guardrails as genai-rag - file content is screened exactly like typed input, not exempted
Out of scopeby design
  • No indexing - files here never become searchable by any other feature
  • No citations/knowledge-sources fields in the response - there's no KB to cite
  • Stateless across sessions - re-attach files each new session; a session's memory doesn't carry the file contents forward, only the conversation
3
Personas
employee / manager / hr_support / adminAll four roles - require_role(EMPLOYEE, MANAGER, HR_SUPPORT, ADMIN). A personal, ephemeral tool that touches no shared state, unlike document upload (which is HR_SUPPORT-only).
4
Acceptance criteria
Answers grounded in the attached filesmet

files_used in every response names exactly which attached files the agent actually read.

Email only on real intentmet

The model's own email decision fires only when the current turn explicitly asks for it - confirmed live after two earlier attempts leaked into unrelated turns or under-fired on genuine requests.

Memory knows real email outcomesmet

A later turn's "did you send it?" can answer correctly, since each turn's stored history carries a factual outcome note the user never sees directly.

File content is screened, not trustedmet

Every extracted file's text runs through the same input guardrail as typed questions, independently per file.
