Multi-Agentic RAG

A real LangGraph multi-agent graph - a Planner dispatches to up to 5 domain agents in parallel, a Reviewer checks the combined result.

Overview Spec Architecture Design Decisions

Purpose

Single-Agentic RAG is one agent choosing one tool at a time. Multi-Agentic RAG is a genuinely different graph: a Planner Agent reads the query, decides which of 5 specialized domain agents it actually needs, fans out to them in parallel, then a Reviewer Agent merges and checks the combined result before anything returns to the caller. This is the mode built for questions that span more than one domain at once - a policy lookup plus a live leave balance, say - where running agents one after another would be slower and less coordinated than dispatching them together.

Scope

Covers the full Planner → parallel dispatch → Reviewer graph: 5 real domain agents (vector_kb_agent for the static knowledge base, lms_ops_agent/lms_analytics_agent for A2A calls to hrb_lms_mcp, sql_db_agent, web_search_agent), conditional dispatch via a real LangGraph add_conditional_edges (not a hand-rolled loop), and suggested_follow_up_questions - a response field unique to this mode. Shares the same Redis answer cache as the other two modes, with the live-data exclusion applied at agent-dispatch granularity.

Guardrails are called directly here rather than through the Phase 98 shared core the other two modes use - a known, flagged gap (see Decisions), not yet migrated. Does not have a caller-tunable iteration cap - unlike Single-Agentic RAG's max_iterations, this mode's step count is just however many agents the Planner actually dispatches to, plus Planner and Reviewer themselves.

High-level workflow

  1. 1Plan - the Planner Agent reads the query and decides which domain agents it needs.
  2. 2Dispatch - a conditional edge sends the query to those agents, in parallel where the graph allows.
  3. 3Domain agents run - each queried agent does its own real work (KB search, live A2A call, SQL, web search) independently.
  4. 4Review - the Reviewer Agent reads every dispatched agent's result and merges them into one coherent answer.
  5. 5Respond - the final answer returns with tasks naming exactly which agents ran, plus suggested follow-up questions.

Where this fits in the HR Benefits RAG system

The most capable of the three read paths, built on the same index and most of the same guardrail/memory machinery as the other two - genai-rag-chat for simple lookups, single-agentic-rag for one tool decision at a time, multi-agentic-rag for questions that genuinely need several specialists working together. Picking the right mode for a question is a real tradeoff this system exposes directly in the UI's "RAG Pipeline:" selector, rather than hiding behind one fixed default.
