Key flow
1Input guardrail check (check_input, called directly - not through the shared core), query normalization.
2Cache lookup on the pipeline-namespaced key.
3On a miss: Planner node decides which of the 5 domain agents this query needs, dispatches via conditional edges.
4Each dispatched domain agent runs its own tool-calling/retrieval; Reviewer Agent checks the combined result.
5Output guardrail (check_output, also called directly), cache write (if no live-data tool was used), conversation-turn save.
