Reading the diagram

A client registers a document and gets a presigned S3 URL back, then PUTs the file straight to S3 - the API never touches the bytes. That upload triggers an SQS message, which Lambda picks up and runs through the same parsing/chunking/embedding/indexing pipeline the synchronous upload path also uses. Every stage writes its own status to Postgres, so a client can poll for progress at any point. The "Indexing Microservices" lane is the target state - today it's one Lambda function running all four stages inline, not four separate containerized services.
