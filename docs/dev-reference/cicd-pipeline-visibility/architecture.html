architecture - system layers and data flow

CI/CD Pipeline Visibility

GitHub Actions stays the single source of truth for both run state and logs - this feature reads it, correlates it with the eval-gate results already in Postgres, and renders one live view. Nothing here stores or re-hosts a log.

What's genuinely new vs. reused
Reused as-isno change

GitHub as the system of record; github_actions_client.py's existing auth/never-raises pattern; eval_run_store's schema; the Admin Dashboard's existing RBAC gating (Engineering Admin only).

New surface areato build

One new client method (jobs-for-a-run), one new route, one new frontend component (stepper) with a polling hook. No new table - job/step detail is fetched live each time, never persisted (GitHub already persists it).
