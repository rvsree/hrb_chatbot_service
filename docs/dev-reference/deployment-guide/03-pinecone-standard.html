Pinecone as the Standing Vector Store

Milestone 1 — small, fast, and a genuine prerequisite for Milestone 3 (batch ingestion), not just a convenient first step.

This is a hard technical dependency, not sequencing preference. Lambda's filesystem is ephemeral — ChromaDB's persistent mode writes to local disk, which doesn't survive or even make sense across Lambda invocations. The batch-ingestion Lambda cannot use ChromaDB at all. Pinecone must be the genuinely active vector store before that Lambda handler can work — this is why it comes first, confirmed.

Standing decision: AWS always uses Pinecone

Per your direction — from now on, every AWS deployment uses Pinecone as the vector store, not ChromaDB. Local dev keeps ChromaDB (file-based, zero setup, no network dependency), the same way local dev keeps SQLite for metadata while AWS uses Postgres. Same local/cloud split, now applied consistently to both backends:

ConcernLocal devAWS (always)
Vector storeChromaDB (persistent, file-based)Pinecone
Metadata storeSQLitePostgres (Neon) — pending Phase 81's fallback fix before full cutover

Open question, worth deciding explicitly: eval-gate.yml (the CI release gate, Phase 80) deliberately runs against ACTIVE_VECTOR_DB=chromadb on a fresh GitHub Actions runner — no external vector DB service needed, keeps CI fast and free of a live dependency. If production always uses Pinecone, the CI gate is testing a different vector store than what actually ships. Worth a conscious decision: keep CI on ChromaDB for speed (accepting the fidelity gap), or extend the gate to also exercise Pinecone before this becomes a blind spot.

Recommend running this full matrix manually once (via Postman — both postman/environments/local.postman_environment.json and aws.postman_environment.json exist for exactly this) right after the env var fix.

Golden dataset gate applies here too. Before this milestone is considered done and merged to master, run eval-gate.yml (gh workflow run eval-gate.yml) and confirm a PASS verdict. See the milestone plan for how this fits across every feature.
