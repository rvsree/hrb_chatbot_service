Neon Postgres

What schema and data actually exist today — verified by querying Neon directly, not assumed from the phase history.

Did we create tables and insert data?

Partially, and worth being precise about what actually happened:

✓ Connectivity verified — live App Runner service successfully connects to Neon (confirmed via GET /health?metadata_provider=postgres).

✓ One table auto-created — documents (the document-metadata table), via a CREATE TABLE IF NOT EXISTS that ran the first time the code touched Postgres (a health check). 0 rows — no data inserted.

○ Three tables NOT created yet — conversation_turns, embedding_cache, answer_cache. Each is created lazily, the same way, but only the first time a real request actually exercises that code path. Since production has only served health checks so far, these don't exist yet.
Java / Spring BootThis project
Flyway / Liquibase migration scripts, versioned, run explicitly on deployNo migration tool. Each Postgres client (postgres_client.py, conversation_store.py, embedding_cache.py, answer_cache.py) runs its own CREATE TABLE IF NOT EXISTS the first time it's used.
spring.jpa.hibernate.ddl-auto=updateConceptually identical — schema appears automatically from code, not from a separate script you run
A seed-data script / data.sqlDoesn't exist — no data has been seeded into Neon

This is fine at current scale (matches how SQLite/local Postgres already worked all session) but is worth knowing: there's no schema version history, and a destructive schema change to any of these tables has no rollback path beyond manual SQL.

Where to look in Neon's console

  1. console.neon.tech → your project → Tables (left sidebar)
  2. Select the HR_Benefits database to see the live table list and row counts — the direct equivalent of opening a schema browser (DBeaver/pgAdmin) against a Spring Boot app's datasource
  3. Monitoring tab — connection count, compute usage — relevant since Neon's free tier auto-suspends the compute after inactivity (first query after a suspend has a brief cold-start delay, worth knowing if a health check ever times out unexpectedly)
