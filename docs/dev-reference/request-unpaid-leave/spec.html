Request Unpaid Leave

A structured leave request, routed through a real human-in-the-loop LangGraph that pauses for a specialist's decision and resumes days later - not a chat question.

Spec Architecture Design Decisions
1
Intent

Four leave types (Unpaid, Critical CareGiver, STD, LTD) that always need a specialist's human judgment, not just a manager's rubber stamp - submitted as a structured form with an optional supporting document, routed through a real HITL (human-in-the-loop) workflow that genuinely pauses mid-process until an HR specialist reviews and decides, then resumes and notifies the employee. The specialist's decision itself is never an LLM call - only the intake validation and the specialist-facing summary are.

2
Scope
Live todaybuilt
  • A 6-node LangGraph with a real interrupt() pause point, Postgres-checkpointed - survives a redeploy, not just an in-memory wait
  • Presigned S3 upload for a supporting document, into a bucket separate from both KB ingestion and the GenAI Chat Workflow's in-memory-only files
  • A specialist review queue (GET /pending, GET /all) with an LLM-generated plain-English review brief per request - recommends nothing, summarizes only
  • Resolution (POST /resolve) resumes the exact paused graph run, writes the decision, sends an SES email, and records the email as a produced artifact
  • An employee-facing "My Requests" view (GET /my-requests) showing status, decision, HR comments, and the specialist's name
  • Admin-only cleanup tooling (list all / hard-delete a request and its cascade) - separate from the HR decision path itself
Out of scopeby design
  • Not built into the GenAI Chat Workflow's attach-files popup - that agent deliberately has no MCP access at all, a foundational scoping decision this feature doesn't reverse
  • HR_SUPPORT cannot file a request through this flow - they review requests, they don't submit their own through it
  • ADMIN cannot resolve a request - a deliberate, flagged conflict with "admin is a superuser," not yet resolved (see Decisions)
3
Personas
employee / manager / admin - submittingrequire_role(EMPLOYEE, MANAGER, ADMIN) on upload-url/request/my-requests - HR_SUPPORT deliberately excluded.
hr_support - reviewing & decidingrequire_role(HR_SUPPORT) only on /resolve - the one real decision action, deliberately not opened to ADMIN.
admin - cleanup onlyCan list and hard-delete requests (data management), cannot approve or reject one (an HR decision) - see Decisions for the flagged tension in this split.
4
Acceptance criteria
The pause is real, not simulatedmet

A request genuinely stops mid-graph and survives a process restart - confirmed via Postgres checkpointing, not an in-memory flag that would be lost on redeploy.

No orphaned uploadsmet

A document manifest row is registered at upload time, before the leave request exists - a failed submit after a successful upload still leaves a trackable record.

Decision always notifies the employeemet

Resolution always attempts an SES email and records whether it actually sent, as a produced artifact tied to the specialist review row.

Specialist sees real context, not a bare requestmet

Every pending request in the queue carries an LLM-generated review brief plus a link to the real uploaded document.
