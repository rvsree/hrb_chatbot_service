Request Unpaid Leave

A 6-node LangGraph StateGraph behind POST /v1/unpaid-leave/request - pauses for real, mid-graph, on a human decision, then resumes days later from exactly where it stopped.

1
The graph unpaid_leave_agent.py :: _build_graph()
START→ intake→ eligibility_check→ submit→ generate_review_brief→ await_specialist_decision→ finalize→ END
interrupt() fires here - graph genuinely pauses, hours to days, until a specialist decides

Every node runs once, in order - no branching, no retry loop. The real work is the interrupt at await_specialist_decision: langgraph.types.interrupt() actually suspends execution and the checkpointer (AsyncPostgresSaver) persists the entire graph state to Postgres. The process can restart, the request can be redeployed, days can pass - resume_unpaid_leave_decision() picks the exact same run back up from that exact point, not a fresh invocation.

4
A2A communication protocol how hrb_chatbot_service actually talks to hrb_lms_mcp - OAuth2, not a shared database

Every call to hrb_lms_mcp is a real network call over MCP, authenticated with a Bearer token from a standard OAuth2 client-credentials grant (oauth_client.py :: get_access_token()) - not a shared database connection, not a trusted-network assumption. The token is cached in module state (one client identity, one token) and refreshed automatically 30 seconds before it actually expires, not on every call - confirmed directly in the code, not assumed.

submit_unpaid_leave_requestCalled by the submit node - creates the real leave_requests + hitl_requests rows in one call.
set_review_briefCalled by generate_review_brief - stores the LLM-written specialist summary on the HITL request.
resolve_hitl_requestCalled by finalize on resume - writes the decision, flips status.
record_produced_artifactCalled by finalize right after a successful decision email - logs it as a real A2A Artifact on the review row.

5
State & memory management what actually survives the pause, and where it lives

The graph's entire working memory is one typed dict, UnpaidLeaveState - every field below is what gets durably checkpointed to Postgres the moment interrupt() fires, and what resume_unpaid_leave_decision() reads back days later:

employee_idstart_dateend_date purposeleave_type_codedocument_reference is_repeat_within_12_monthsintake_notessubmit_result review_briefdecisionfinalize_result

Persistence is langgraph.checkpoint.postgres.aio.AsyncPostgresSaver - LangGraph's own checkpoint tables, in the same Postgres database every other store in this project uses. Resuming never replays earlier nodes: Command(resume=decision_payload) loads the exact checkpointed state and continues from await_specialist_decision directly into finalize.

A real platform-specific fix, not a hypothetical

AsyncPostgresSaver needs real async psycopg, which raises psycopg.InterfaceError outright on Windows' default ProactorEventLoop - confirmed directly. Every graph run executes on a freshly constructed SelectorEventLoop, in its own worker thread, local to this one module - the main app's own event loop (uvicorn, every other async client) is never touched.
