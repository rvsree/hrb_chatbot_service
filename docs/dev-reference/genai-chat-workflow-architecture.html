Chat GenAI Workflow

Ad-hoc document Q&A, attached directly in the chat composer — up to 3 files (PDF/Word/CSV), answered by a ReAct agent with LLM-only tool calls. Deliberately separate from the main RAG pipeline: no S3, no vector store, no persisted metadata. Design only as of this page — nothing below is built yet.

Decisions made without waiting for approval, flagged for review

#DecisionWhy
1One combined request, not attach-then-askNo server-side temp storage needed between steps - simplest shape, nothing to leak or clean up
2DOCX via stdlib zipfile+ElementTree, not python-docxAvoids a new-library approval while the user is away; cruder (no tables/formatting) - flagged as a future upgrade
3Open to all roles, not just HR_SUPPORTPersonal ephemeral tool, doesn't touch shared KB state
4Reuse existing guardrails, don't build new onesSame content-safety concern as the earlier "upload guardrails" ask - file content still reaches the LLM
5~12k chars/file truncation capProtects the model's context window; truncation is shown to the user, never silent
6Stateless across turns - re-attach each messageSimplest to start; flagged as a real limitation, not solved here
7AWS SES for email, via boto3Already a dependency, same AWS account as everything else - needs one real one-time step: verifying a sending identity in the SES console (starts in sandbox mode)
