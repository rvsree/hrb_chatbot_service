Chunking Strategy

One function dispatch table (CHUNKING_STRATEGIES) over 7 real LangChain-backed splitters, with a shared table-extraction step and oversized-chunk safety net around all of them.

1
API contract

POST /v1/genai-rag/ingest-document/documents/{document_id}/rechunk - the only HTTP entry point; a fresh upload calls chunk_text_with_sections() directly inside index_document(), no separate route.

Body fieldTypeNotes
user_profileobjectSame UserProfile shape every route uses
chunk_info.chunking_strategystrOne of the 7 keys in CHUNKING_STRATEGIES - an unknown value raises a ValueError
chunk_info.chunk_sizeint, optionalOmitted lets the backend auto-pick via decide_chunk_size()
chunk_info.chunk_overlapint, optionalDefaults to 150 if omitted
2
Request flow
split tables out→ resolve strategy→ resolve chunk_size→ run strategy function→ oversized-chunk safety net→ reattach table blocks

Strategy resolution: explicit value wins; otherwise decide_chunking_strategy() sniffs markdown heading lines (#) first, then HTML heading tags (<h1>/<h2>/<h3>), then falls back to none (document ≤ 1000 chars) or recursive (longer) - semantic and document_structure are never reached by auto-selection.

3
The 7 strategies
StrategyReal techniqueAuto-selected?
fixedCharacterTextSplitter, single \n separator - fast, may cut a sentence in halfno (explicit-reachable, not auto)
recursiveRecursiveCharacterTextSplitter - paragraph → line → sentence → hard cut, the general-text defaultyes - fallback when nothing else matches
semanticSemanticChunker - embeds each sentence, splits where meaning shifts; 1 embedding call per sentenceno, explicit-only
markdownMarkdownHeaderTextSplitter on #/##/###yes - when a #-prefixed line is found
htmlHTMLHeaderTextSplitter on <h1>/<h2>/<h3>yes - when an HTML heading tag is found
noneNo splitting at all, just the size-cap safety netyes - for documents ≤ 1000 chars
document_structureThis project's own splitter on real "Section N:"/"N.N Subtitle" headings, tagging each chunk with a stable section_idno, explicit-only
4
Real constraints (NFRs)
ConstraintValueWhy
Default chunk size1000 charsKeeps a chunk topically focused without over-fragmenting
Default overlap150 charsRoughly a sentence - a boundary-split sentence still appears whole somewhere
Whole-document threshold≤ 1000 chars → noneNot critical for short documents, matches the workshop's own takeaway
Large-document chunk size> 10,000 chars → 1500Avoids 10+ tiny fragments, each losing surrounding context
Oversized-chunk capApplied to all 7 strategiesPhase 156 extended Phase 149's semantic-only fix after markdown/html/none showed the same uncapped-giant-chunk risk
Table handlingAlways pulled out, always wholeA table split mid-row is useless at retrieval time, regardless of strategy
