42 real findings, not fixed genuine system-behavior questions, flagged for a deliberate future phase

↳
No query contextualization before retrieval: retrieve_chunks() embeds a follow-up's raw text directly - "is that available right away?" never gets rewritten against conversation history before the vector search. The LLM does see full chat history at generation time, but the system prompt strictly forbids answering from anything but the freshly-retrieved context, so a pronoun-dependent follow-up that misses retrieval gets a correct-but-unhelpful decline instead of the real answer sitting in its own conversation history. Affects both genai-rag and multi-agentic-rag modes identically (conv-01, conv-06). The standard fix is a query-condensation step (rewrite the follow-up into a standalone search query using chat history, one extra LLM call) - not built here, a real architecture decision for a future phase.

5Known gap - Dynamic retrieval strategy has zero golden-dataset coverage found 2026-10-24, auditing for blind spots in these results

⚠
Neither dataset pins a search_strategy at all - both golden_dataset.json and golden_dataset_conversational.json cases always omit the field, so every case above ran under whichever strategy was the system default on the day it was executed. That default changed mid-stream: Phase 252 ("Dynamic RAG Retrieval," commit c808129, 2026-10-22) added a 6th SearchStrategy value and made hrb_chatbot_ui's own default dynamic instead of similarity - and the conversational tests above were run 2026-10-23, through the real UI, with no override. So every genai-rag case in section 2 (conv-01/02/03/07/08) actually exercised dynamic_strategy_selector.py's heuristic routing, not a fixed strategy - a fact these results never surfaced, because nothing in the harness logs or reports which concrete strategy dynamic resolved to per query. No case anywhere in either dataset explicitly targets dynamic, and none verifies the resolved-strategy value the response itself reports (retrieval_info.search_strategy). This is a real, unaddressed gap, not fixed here - flagging per "flag, don't fix."
