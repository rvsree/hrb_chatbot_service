overview

Common-Libs Connectors

One package, ten logically-grouped installable extras - mapped directly onto hrb_chatbot_service's existing common/clients/ folders - so a service like api_gateway_service never pulls in an LLM or MCP connector it has no business touching.

Overview Spec Architecture Design Decisions

Purpose

Every microservice in the split needs some subset of: a Postgres connector, a vector-store connector, an LLM provider gateway, an MCP client, S3 access, Tavily web search, OAuth2/auth, SES email, a Redis connector, or a CI/CD (GitHub Actions) client - but no service needs all ten. hrb_common_libs exists so each connector is written once and versioned once, while each service only installs the slice it actually uses.

Scope

Covers extraction of the existing Base*Client/Gateway pattern already proven in src/hrb_chatbot/common/clients/ into ten installable extras of one package: observability (new), db, cache, llm, mcp, storage, web, auth, email, ci. Each extra is independently installable; observability is the one every other extra depends on.

Does not cover business logic of any kind - chunking strategy, HITL workflow rules, 401k domain rules stay inside the service that owns them. A connector only knows how to talk to a backend, never what the data means.

High-level workflow

  1. 1Extract each of the 9 existing common/clients/*_client/ folders into its own extra inside one new repo.
  2. 2Add a 10th, new observability extra (logging/request_id/retry/circuit-breaker - see the NFR Components doc).
  3. 3Tag a version (v0.1.0); every consuming service pins to a tag, never a floating branch.
  4. 4Each service declares only the extras it needs in its own requirements.txt - see the per-service dependency matrix in Design.
  5. 5A version bump is deliberate - no service silently inherits a breaking change from another service's reason to upgrade.

Where this fits in the microservices rollout

Phase 0 work, alongside the Postgres schema migration and the NFR Components layer (see microservices-rollout-plan.html) - every service built afterward is written against this from its first commit.
