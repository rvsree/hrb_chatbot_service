Common-Libs Connectors — Spec

Requirements and constraints for the shared connector package, extracted from and replacing nine existing common/clients/ folders.

Overview Spec Architecture Design Decisions
1Personas

Same as NFR Components - the builder of each new service, deciding at its first commit which backends it's actually allowed to touch.

2Functional requirements
  • MUSTEach of the 10 extras (observability, db, cache, llm, mcp, storage, web, auth, email, ci) is independently pip-installable via hrb_common_libs[extra_name].
  • MUSTInstalling any extra other than observability transitively installs observability - every connector call is loggable/retryable by default.
  • MUSTInstalling the db extra does not pull in llm, mcp, or any other unrelated extra - no accidental coupling.
  • MUSTEvery public class/function keeps the existing Base*Client ABC + Gateway shape already proven in this codebase - this is an extraction, not a redesign.
  • SHOULDEach extra's connector classes accept a constructor-injected logger/retry policy from the observability extra rather than instantiating their own.
3Acceptance criteria
  • pip install hrb_common_libs[db] in a clean virtualenv does not install openai, mcp, boto3, or tavily-python as transitive dependencies.
  • A diff to hrb_common_libs's llm extra that doesn't touch db/cache/etc. does not force a version bump for a service that only installed db.
  • Every extracted client's existing test suite (currently in tests/hrb_chatbot/common/clients/) passes unmodified against the extracted package, proving behavior didn't change in the move.
4Constraints
  • Python 3.12 only, matching every consuming service.
  • No new backend dependency gets introduced during extraction - this is a move, not an upgrade.
  • Pinned via git tag in every consumer's requirements.txt - never a floating branch reference (see Decisions).
