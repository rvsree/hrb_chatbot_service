api_gateway_service — Design

Schema, deployment, requirements.txt, and .env — exactly what this service needs, nothing copied from another.

Overview Spec Architecture Design Decisions
1No new Postgres schema

Unlike every other service, the Gateway owns no business data. Rate-limit counters live in Redis (ephemeral, TTL'd), not Postgres. If session storage is ever needed beyond a bearer token, it's a Redis key, not a new platform_*-style schema - there's nothing here worth persisting past a request's lifetime.

2Route-to-service map (config, not code)
ROUTE_MAP = {
    "/v1/genai-rag/ingest-document": "RAG_INGESTION_SERVICE_URL",
    "/v1/genai-rag-retrieval": "RAG_RETRIEVAL_SERVICE_URL",
    "/v1/single-agentic-rag-retrieval": "RAG_RETRIEVAL_SERVICE_URL",
    "/v1/multi-agentic-rag-retrieval": "RAG_RETRIEVAL_SERVICE_URL",
    "/v1/admin": "RAG_RETRIEVAL_SERVICE_URL",   # platform package, co-located
    # added later, not yet live:
    # "/v1/chat-audio": "CHAT_AUDIO_SERVICE_URL",
    # "/v1/employee-401k": "PLAN_401K_SERVICE_URL",
}

Same pattern already proven for HRB_LMS_MCP_URL - a plain env var per downstream service, not a service-discovery mechanism. Adding a new backend is a config change, not a code change.

3requirements.txt
fastapi
uvicorn
httpx                    # forwarding requests to backend services
pydantic
git+https://github.com/rvsree/hrb_common_libs.git@v0.1.0#egg=hrb-common-libs[observability,db,cache,auth]

Notably absent: openai, langchain, mcp, boto3, tavily-python, psycopg for any RAG-specific table. This service cannot accidentally call an LLM or an MCP tool even if someone tried - the dependency isn't installed.

4.env.example
# CORS
ALLOWED_ORIGIN=https://hrb-chatbot-ui.rvsree.dev

# Rate limiting
REDIS_URL=
RATE_LIMIT_PER_MINUTE=60

# Downstream services
RAG_INGESTION_SERVICE_URL=
RAG_RETRIEVAL_SERVICE_URL=

# Observability (from hrb_common_libs)
LOG_FORMAT=json
LANGSMITH_API_KEY=
LANGSMITH_PROJECT=api_gateway_service

No OPENAI_API_KEY, no PINECONE_API_KEY, no HRB_LMS_MCP_OAUTH_CLIENT_SECRET - those stay in the services that actually call those backends.
