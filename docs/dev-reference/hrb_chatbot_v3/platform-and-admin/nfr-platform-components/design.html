Concrete API surface, config convention, and package layout - the part a consuming service's code actually imports.

Overview Spec Architecture Design Decisions
1Package

Ships as the observability extra of hrb_common_libs (see the Common-Libs Connectors doc) - every other extra (db, cache, llm, ...) depends on it, so installing any extra pulls it in automatically.

pip install "git+https://github.com/rvsree/hrb_common_libs.git@v0.1.0#egg=hrb_common_libs[observability]"
2API surface (sketch)
from hrb_common.observability import get_logger, request_id_middleware, RequestContext
from hrb_common.resiliency import with_retry, CircuitBreaker
from hrb_common.security import read_secret

logger = get_logger("rag_retrieval_service")

@with_retry(max_attempts=3, backoff_base_seconds=0.5)
def call_llm_provider(...): ...

breaker = CircuitBreaker(name="mcp_hrb_lms_mcp", failure_threshold=2, cooldown_seconds=10)
with breaker:
    result = call_mcp_tool(...)

api_key = read_secret("OPENAI_API_KEY")  # Secrets Manager in prod, .env locally - same call either way
3Config convention

CIRCUIT_BREAKER_FAILURE_THRESHOLD2breaker instance
CIRCUIT_BREAKER_COOLDOWN_SECONDS10breaker instance
LOG_FORMATjsonservice (env var)
