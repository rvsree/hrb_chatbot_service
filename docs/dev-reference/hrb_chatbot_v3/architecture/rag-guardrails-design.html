RAG Guardrails Blueprint

What Gates 1 (input) and 6 (output) of docs/rag-validation-gates.html actually check, at implementation detail. Gate 5 (live faithfulness) is the one deliberate exception - still red, on purpose.

Most of this page is built now, via NeMo Guardrails (`nemoguardrails==0.24.1`, `LLMRails.check_async()`) - not the stdlib regex/keyword approach originally sketched here. Two functions, `ai/pre_processing/guardrails_input.py :: check_input()` and `ai/rag_pipeline/response_generation/guardrails_output/ :: check_output()`, cover PII masking, prompt-injection/jailbreak, and toxicity in one call each. The one deliberate exception: faithfulness/groundedness (Gate 5) stays unbuilt as a live check - DeepEval's `FaithfulnessMetric` does that job offline instead (Phase 8), so it isn't duplicated.
