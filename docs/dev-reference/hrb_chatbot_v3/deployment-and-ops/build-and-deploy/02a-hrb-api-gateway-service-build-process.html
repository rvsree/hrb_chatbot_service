Build Process — hrb_api_gateway_service

Second in the sequence - what the UI actually talks to. Simplest Dockerfile of the 6 containerized services: stateless, no PII-masking guardrail, no data/ directory.

1Docker image - 2-stage build Dockerfile, build context = repo root

stage 1 — builder
FROM python:3.12-slim AS builder3.12 exactly, matching every other service
↓
apt-get install gitNeeded only because requirements.txt pins hrb-common-libs via a git+https URL, not a published PyPI package - pip needs git to clone that tag
↓
COPY requirements.txt + pip install into /opt/venvRequirements copied before source, so an ordinary code edit reuses Docker's cached install layer
stage 2 — runtime
↓
FROM python:3.12-slim AS runtimeFresh base - none of stage 1's build tooling (gcc, git) reaches the final image
↓
apt-get install curl + useradd hrbgateway (uid 10001)curl only for the HEALTHCHECK; runs as non-root
↓
COPY --from=builder /opt/venv /opt/venvThe only thing carried over from stage 1 - the installed dependencies, not the build tools
↓
COPY src ./src, EXPOSE 8100No data/ directory, no S3 upload dir - this service is genuinely stateless
↓
CMD uvicorn gateway.main:app --app-dir src--app-dir src, not src.gateway.main:app - this repo's own modules import each other as bare from gateway import ..., confirmed live when the other form 404'd with ModuleNotFoundError

2Real CI/CD pipeline same shape all 5 containerized backend services share

1. Checkout + configure AWS credentialsScoped deploy user, this repo's ECR + App Runner service only
↓
2. ECR loginaws ecr get-login-password | docker login
↓
3. docker buildx build (build-only)--provenance=false --sbom=false --output ...,oci-mediatypes=false,push=false - builds and warms the cache, doesn't push yet
↓
4. docker buildx build (push)Identical command, push=true - a cache hit, not a second build; splits build/push into separately-timed CI steps
↓
5. aws apprunner start-deploymentExplicit call - AutoDeploymentsEnabled: false means a new ECR image alone never triggers a redeploy
↓
6. Poll until RUNNING30 checks × 10s - fails loudly if the service lands on anything but RUNNING
↓
7. Smoke testcurl --fail $APP_RUNNER_URL/ping
⚠
The 3 build flags matter, not just the first two: losing --provenance=false, --sbom=false, or oci-mediatypes=false reintroduces a real App Runner bug - the image pulls successfully, then silently never starts (zero application logs). Found the hard way in hrb_chatbot_service's own Phase 10, carried into every service's workflow since.
