Resolved · Root CauseLinks that only ever worked on your own machine

README.md in both repos linked "up and out" to a folder that didn't exist on GitHub Fixed

Both repos' READMEs used relative links like ../docs/architecture/platform-overview.html, which only resolved locally - on GitHub, hrb_chatbot_service, hrb_chatbot_ui, and hrb_emp_assist are three separate repos with no parent to go "up" into.

Fix
hrb_emp_assist made public (scanned clean first - no secrets, no key files), then all ~12 escaping links across both READMEs/CLAUDE.md converted to absolute https://github.com/rvsree/hrb_emp_assist/blob/master/... URLs.
Verified
Every converted URL spot-checked with a direct fetch - real 200, not 404.
Even a correctly-linked .html opened as source code on GitHub Fixed - with a caveat on .drawio, see below

GitHub's blob viewer shows .html files as syntax-highlighted source, never a rendered page - confirmed, GitHub forces Content-Type: text/plain on every raw file, including on raw.githubusercontent.com (their own anti-XSS hardening, not fixable from this project's side).

Fix
Added a "Viewing the architecture docs" note near the top of both READMEs, pointing reviewers at the live Admin Dashboard's doc viewer (which renders these correctly via presigned S3 URLs) instead of raw GitHub browsing.
.drawio diagrams opened as raw XML even through the app's own, working doc viewer Fixed - the deeper layer of "opening code instead of diagrams"

Found on the 2nd review pass: every diagram's link already worked (all 86 registered docs confirmed loading real content) - the actual gap was what the browser does with a successful response. S3 serves .drawio files as Content-Type: application/xml with no Content-Disposition, so the browser displays raw XML inline instead of downloading it - true inside this app's own admin-docs viewer, not just on GitHub.

Fix
The presigned URL now forces a real file download for .drawio (ResponseContentDisposition=attachment) - matching this project's own already-documented intent ("a .drawio file is a download-and-open-in-draw.io artifact") that had never actually been implemented. .html docs are unaffected.
Verified
Live header check post-deploy: the diagram doc now returns Content-Disposition: attachment; filename="diagram-current-state.drawio"; an HTML doc checked the same way shows no such header, confirmed unaffected.
