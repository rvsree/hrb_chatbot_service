Critical · Root CauseLinks that only ever worked on your own machine

README.md in both repos links "up and out" to a folder that doesn't exist on GitHub Breaks on first click

Both repos' README.md use relative links like ../docs/architecture/platform-overview.html. Locally this resolves fine because hrb_chatbot_service happens to sit as a subfolder of a shared hrb_emp_assist folder on your own disk. But on GitHub, hrb_chatbot_service, hrb_chatbot_ui, and hrb_emp_assist are three separate, independent repositories - there is no parent folder to go "up" into. The link is simply dead.

This is almost certainly the exact thing your friends hit - it's the first set of doc/diagram links in the README, and every one of them fails the same way.

Confirmed by
Walking every relative link in both READMEs and checking whether it resolves inside the repo's own git root; 6 in hrb_chatbot_service/README.md, 6 in hrb_chatbot_ui/README.md, all of the form ../docs/... or ../hrb_chatbot_service/docs/....
Where
Both repos' README.md and CLAUDE.md, plus docs/agent-reference/testing-strategies.md (one link).
Even a correctly-linked .html or .drawio file opens as source code on GitHub Not a bug - a hosting limit

This is the "opening the code instead of actual diagrams" symptom, and it's not fixable by changing a link - GitHub's blob viewer shows .html files as syntax-highlighted source text, never as a rendered page. Clicking "raw" doesn't help either: GitHub forces Content-Type: text/plain on every raw file (their own anti-XSS hardening), confirmed directly against raw.githubusercontent.com. The same applies to .drawio diagrams - GitHub has no native renderer for them at all, so they show as raw XML.

The project's own docs already serve these correctly when viewed through the live Admin Dashboard (presigned S3 URLs, confirmed working all session) - the gap is that nothing tells a GitHub-only visitor that's where to look.

Confirmed by
Direct curl against both the GitHub blob URL and the raw URL for a real doc file - headers show Content-Type: text/plain on the raw file every time.
Fix is a choice, not a patch
Point reviewers at the live Admin Dashboard's doc viewer instead of raw GitHub browsing, and/or stand up GitHub Pages for the docs tree so .html files actually render as pages. Mermaid diagrams are unaffected - GitHub renders those natively already (confirmed: the README's tech-stack diagram is Mermaid and displays fine).
