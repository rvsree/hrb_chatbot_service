call_type - a real bug this session, worth keeping visible

call_type: "agent_call" means one specific thing: this query is expected to trigger genai-rag's own deterministic MCP keyword bypass (is_leave_balance_query() / is_leave_history_query()). It does not mean "this tests agentic routing in general" - that's a different concept (routing-accuracy, above), and conflating the two produces a real, catchable test failure:

CaseTaggedResultWhy
routing-leave-history-01agent_callCorrectMatches genai-rag's real keyword bypass
routing-analytics-01agent_call (initial, wrong)Caught by test suiteDoesn't match any keyword bypass - retagged llm_call
routing-web-search-01agent_call (initial, wrong)Caught by test suiteSame - retagged llm_call, with a note added to the case's own JSON
Why this matters for an audit, not just a test pass: routing-accuracy and groundedness are independent signals - an agent can call the wrong tool and still produce a plausible-reading (but wrong) answer that a groundedness judge alone wouldn't catch, since it isn't checking "was this the right tool," only "does this answer look supported." Routing-accuracy is the check that closes that gap.
