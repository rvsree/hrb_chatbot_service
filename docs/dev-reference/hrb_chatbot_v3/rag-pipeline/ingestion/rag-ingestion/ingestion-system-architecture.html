No queues, no DLQ, no separate microservices — unlike a typical async-ingestion target state, every stage above runs inline, in the same request, in one FastAPI process. A real async design (S3 presigned upload + Lambda, triggered after this request returns) exists as a design only, not built - see docs/agent-reference/S3-ASYNC-UPLOAD-DESIGN.md. The only queue-like behavior today is save_uploads() looping files one at a time within a single batch request - not a real queue, no retry/backoff/poison handling.
