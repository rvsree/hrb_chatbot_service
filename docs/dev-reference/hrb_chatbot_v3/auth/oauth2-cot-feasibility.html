Chain-of-Thought / Reasoning-Trace Capture logging an LLM's intermediate reasoning steps, not just its final answer
Feasible, but defer
genai-rag today

One retrieval call, one generation call. There is no real "internal reasoning process" to capture yet - the pipeline doesn't decide anything, it just runs the same two steps every time. A trace of this would show almost nothing beyond what a normal log line already shows.

single/multi-agentic-rag, once built

A real agent loop genuinely reasons: which tool to call, why, what came back, whether to call another tool. That's exactly the kind of internal process worth capturing - the harness has something real to record.

Two different things, often conflated
CoT prompting (asking the model to write "step by step" in its answer text) vs. logging the model's actual internal steps. Neither is built. The first is a prompt-engineering choice; the second is an observability concern.
Logging already has a home
LangSmith (built, deliberately off) traces every LangChain step automatically the moment it's turned on - no separate manual reasoning-log mechanism needs building from scratch.
common/observability/langsmith_tracing.py
What a harness would add
A wrapper that runs an agent conversation and writes each step (tool chosen, input, output, reasoning text) to structured storage for later review - same shape as golden_dataset_harness.py, applied to agent steps instead of eval scores.
same pattern as Phase 8's harness
Why defer, not "not feasible": building this now means designing a data shape for steps that don't exist yet. Once single-agentic-rag's tool-calling loop is real, the actual shape of "a step" becomes obvious from the code, instead of guessed at in advance.
