Single-Agentic RAG

A real ReAct tool-calling agent - decides for itself whether to search the knowledge base, check a leave balance, or answer directly.

Overview Spec Architecture Design Decisions

Purpose

GenAI RAG Chat always retrieves, then always generates - it never decides anything. Single-Agentic RAG is the step up from that: a real ReAct loop where the LLM itself chooses, per query, whether to search the static knowledge base, call a live tool for the caller's own leave balance or leave history, or just answer directly - iterating up to a caller-set cap rather than following one fixed path.

This is the first mode in the system where "which tool to use" is a real model decision, not a keyword match or a fixed pipeline step - and the first place live, personal data (a real leave balance, not a document) enters an answer.

Scope

Covers the full ReAct tool-calling loop: 3 real tools (SearchKnowledgeBase, GetLeaveBalance, GetLeaveHistory - the latter two real A2A calls to hrb_lms_mcp over OAuth2), a caller-set max_iterations bound, full guardrails and conversation memory via the shared Phase 98 core, and the same Redis answer cache the other modes share - with live-data-tool answers excluded from caching, since a cached leave balance could go stale the moment it's reused.

Does not cover parallel multi-agent dispatch across several domain agents at once (that's Multi-Agentic RAG, a genuinely different LangGraph graph) - this mode is always one agent, deciding one tool call at a time.

High-level workflow

  1. 1Input guardrail - the query is checked via the shared guarded_pipeline.py core, same as every other mode.
  2. 2Reason - the agent decides whether it has enough information to answer, or needs a tool.
  3. 3Act - if a tool is needed, it calls one of the 3 (knowledge base search, or a live A2A call for the caller's own leave data).
  4. 4Repeat - steps 2-3 loop until the agent has what it needs or max_iterations is hit.
  5. 5Generate - a final answer is written from whatever was gathered, with tools_used naming exactly which tools actually ran.
  6. 6Output guardrail + memory - checked and saved, same shared core as every other mode.

Where this fits in the HR Benefits RAG system

One of three read paths over the same index and the same shared guardrail/memory/logging core. Where GenAI RAG Chat is the fixed baseline, Single-Agentic RAG is where real tool-calling judgment enters the system - and where a leave-balance question first becomes answerable at all, since GenAI RAG Chat's own MCP fast-path only covers a narrow keyword set, not a real reasoning loop. Multi-Agentic RAG then takes this same tool-calling idea and parallelizes it across several specialized agents at once.
