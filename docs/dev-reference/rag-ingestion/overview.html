RAG Ingestion

How a document becomes part of the knowledge base every RAG query mode searches.

Overview Spec Architecture Design Decisions Interview FAQ

Purpose

Every answer this chatbot gives is only as good as what's actually indexed. RAG Ingestion is the boundary between a raw HR policy document and a chunk of text a query can retrieve and cite - it takes a PDF, extracts its text, splits it into chunks, embeds those chunks, and writes them into the vector store the rest of the system searches.

Without this pipeline running correctly, every other RAG feature in the app - plain retrieval, the single-agent loop, the multi-agent graph - has nothing real to answer from.

Scope

Covers getting a document from "uploaded" to "searchable": two real upload paths (a synchronous one for interactive/batch uploads, an asynchronous one for larger files that shouldn't block on indexing time), content-hash deduplication so the same file never gets indexed twice, six selectable chunking strategies, and status tracking through every stage so a caller always knows exactly where a document is in the pipeline.

Does not cover how a query retrieves what this pipeline indexed (that's Retrieval Strategies), or how a chat mode uses retrieved chunks to generate an answer (that's GenAI RAG Chat and the two agentic modes) - this feature's job ends once a document is indexed and searchable.

High-level workflow

  1. 1Register - a document is recorded with a unique id, before any bytes exist yet (the async path) or alongside them (the sync path).
  2. 2Upload - the file lands in S3, either inline with the request or via a direct client-to-S3 PUT.
  3. 3Parse - text is extracted from the PDF.
  4. 4Chunk - the text is split using the selected (or auto-chosen) strategy.
  5. 5Embed - each chunk gets a real vector embedding.
  6. 6Index - chunks and embeddings are written to the vector store.
  7. 7Searchable - the document is now part of what every RAG query mode can retrieve from.

Where this fits in the HR Benefits RAG system

This is the write path. Everything else RAG-related in this app is the read path: GenAI RAG Chat, Single-Agentic RAG, and Multi-Agentic RAG all query the same index this pipeline populates, through the strategies described in Retrieval Strategies. A document uploaded here today is what makes a policy question answerable tomorrow - there's no retrieval feature in this system that doesn't ultimately depend on this one having run correctly first.
