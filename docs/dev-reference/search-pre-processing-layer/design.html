1STM key shape (Redis)
stm:{conversation_id}
  -> JSON list, last N turns (role, content, timestamp)
  -> TTL: 2h of inactivity (configurable)

# Same key-naming convention already fixed project-wide:
# {service}:{purpose}:{identifier}
rag_retrieval_service:stm:7f3a9c...

Read: GET stm:{conversation_id} - on miss, fall back to conversation_store.get_turns(conversation_id, limit=N) (Postgres) and backfill Redis. Write: append to both Redis (via RPUSH + re-set TTL) and Postgres (unchanged, already happens today) on every turn.

async def assemble_context(user_profile, conversation_id, query) -> RequestContext:
    """One call, gathers everything the chosen pipeline needs."""
    stm = await get_stm(conversation_id)          # Redis, falls back to Postgres
    feedback = await get_latest_feedback(conversation_id)  # surfaced, not yet acted on
    classification = classify_intent(query)         # feeds routing
    return RequestContext(user_profile, stm, feedback, classification)
3Session / state

No new "session" object - conversation_id stays the one identifier, same as today. What changes: the Pre-Processing layer is now the single place that reads/writes it, instead of each pipeline touching conversation_memory.py independently.

4Feedback loop

feedback_store.py stays the system of record, unchanged. This layer adds one read: the most recent feedback vote for this conversation, attached to RequestContext - available for a future routing rule (e.g. escalate to Agentic Workflow after a "not helpful" vote), not acted on in this first version (see Decisions).
